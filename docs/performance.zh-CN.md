# 性能

[English](performance.md)

性能是核心要求。rtex-ts 单独测量包含同步缓冲区处理的延迟；上游论文约 1 ms 的结果不是本包的基准。

## 复现

```sh
npm ci
npm run benchmark -- --pages 10,100,300 --samples 50 --output .ai-notes/performance/local.json
```

先安装 LuaLaTeX、fontspec 和 Latin Modern Roman。合成 article 使用显式分页，每页四段；每个样本修改第一段的一个字符。常驻引擎已预热，不计首次旧段落验证探针。计时从调用 `setDocument()` 前开始，到 `ParagraphUpdate` 事件结束，包含同步文档处理、传输、TeX 和显示列表解码；不含编辑器／渲染器 IPC、字形绘制与屏幕呈现，也不代表 TeXPro 性能。

结构修改、不支持语法、PDF 回退、启动和后台收敛有不同开销。脚本也记录启动和 Node RSS，不统计整个 TeX 进程树内存。运行时避免并行构建和其他重载程序。百分位只描述这些样本，不构成延迟保证。原始结果留在 Git／npm 归档之外。

## 0.1.7 候选版本本机测量

测量日期 2026-11-11（Asia/Shanghai），Apple M1 Pro、macOS ARM64、Node 26.5.0、LuaHBTeX 1.16.0／TeX Live 2023，每份文档测量 50 次修改：

| 页数 | 源码字节数 | 编辑 → 事件 p50 | p95 | p99 | 同步编辑 p50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 | 19,321 | 1.80 ms | 2.39 ms | 2.56 ms | 0.39 ms |
| 100 | 192,571 | 2.66 ms | 3.27 ms | 3.80 ms | 1.33 ms |
| 300 | 578,171 | 4.80 ms | 5.61 ms | 6.12 ms | 3.38 ms |

这是单台机器的合成英文段落数据，不能推广为中文、数学、自定义文档类、所有平台或宿主的同等延迟。每个会话使用全新字体缓存，首次布局约耗时 11.6／13.3／18.5 秒。冷启动与完整排版仍需优化。

优化前，同一机器、相同合成文档的 0.1.1 实现初步测量了 20 个样本，编辑到事件中位数约为 6.43／32.41／190.75 ms。样本数不同，此对比用于定位问题，不是受控统计结论。

## 局部编辑减少了什么开销

段落内部修改只重新分段该段落，再平移后续 UTF-8／行位置；结构或边界修改仍使用完整平衡扫描器。稳定分段匹配使用 Map／Set，避免重复线性搜索；位置计算单次遍历源码区间。响应通过 Node 流和 POSIX FIFO／Windows 命名管道送达，去掉响应文件轮询间隔和持续增长的响应文件。旧段落探针与过期结果检查始终保留。

0.1.7 复用同一上下文的安装结果；后台快照采用有并发上限的异步 I/O，版面行和段落上下文用索引匹配并分批让出事件循环。实时表格不包含完整后台或冷启动耗时，不能用来代表整个应用响应。

## 图片缓存后台对照（0.1.8）

```sh
npm run benchmark:pictures -- --pictures 12 --strokes 150 --samples 20 --output .ai-notes/performance/pictures.json
```

2026-11-11，在相同 M1 Pro/macOS/Node 26.5.0/TeX Live 2023 环境测量。合成文档有 12 张 TikZ 图（每张 150 条半透明线），每页一图，最后一页文字，共 13 页。两组各使用独立会话和新的字体缓存。启动后每组测量20 次：在所有图片之后改一个字符，主动请求完整版面，等待 `LayoutUpdate`；每次先确认常驻导言区已就绪。计时包含快照 I/O、两轮 TeX/辅助处理、缓存操作和版面安装，不含宿主绘制。

| 图片缓存 | 完整布局 p50 | p95 | 首次布局 | 提供的缓存候选 |
| --- | ---: | ---: | ---: | ---: |
| 关闭 | 3.62 秒 | 5.15 秒 | 13.80 秒 | 0 |
| 开启 | 1.05 秒 | 1.43 秒 | 14.65 秒 | 12 |

这组每模式20 次的初步对照，中位数约减少 71%，冷启动没有改善。表中包含所有样本，未剔除异常值。这些数字不代表任意绘图或跨平台加速保证。缓存绘图仍走 PDF 回退，不是实时字形覆盖。独立本机视觉场景保持分页/定位，但在 144 dpi 下有 117 个裁切边框抗锯齿像素不同，因此不保证像素完全相同。普通导出不使用缓存。

## 启动与字体缓存（0.1.9）

```sh
npm run benchmark:startup -- --samples 5 --out .ai-notes/startup.json
```

0.1.9 不再强制每个会话使用新的 `TEXMFCACHE`，默认沿用 TeX 安装及已有环境配置。需隔离时传 `fontCacheDir` / `--font-cache DIR`。缓存由 TeX/宿主管理，不随会话关闭删除。

2026-11-11 在上述 M1 Pro/macOS ARM64、Node 26.5.0、TeX Live 2023 上测量：139 字节单页 fontspec/Latin Modern Roman 文档，含行内数学；每组 5 次，顺序交替。每次会话/TeX 进程均为新建，关闭后台预热和图片缓存；“安装缓存”在测试开始前已生成，不清空；“全新独立缓存”每次指定新目录。计时从会话构造开始，首次预览止于 LayoutUpdate，就绪止于 EngineState Ready；不是每个单元的探针通过率，也不含宿主绘制。

| 字体缓存 | 首次预览中位数 | 实时引擎就绪中位数 | 就绪最小–最大 |
| --- | ---: | ---: | ---: |
| 每次全新独立缓存 | 11.74 s | 12.46 s | 11.81–18.18 s |
| 复用已生成的安装缓存（新默认） | 1.83 s | 2.54 s | 2.42–2.97 s |

首次预览中位数降低约 84%，实时就绪约 80%。保留全部样本，包括最慢一次。构建 JavaScript SHA-256：`54fb320f559fb017862a823bf5a60cc4851e3d50b57d49b1e9f0b2b3cd351015`。这是单机、小样本的缓存策略对照，不证明所有文档或平台均有相同速度。**首次安装或缺少字体缓存时仍需生成数据库**：单独初步观察约 11.8 秒才有首个布局，不能宣传为首次安装也只需 1.83 秒。完整排版仍有两轮 TeX 及实时引擎启动开销；更复杂项目需分别测量。
