# 性能

[English](performance.md)

性能是核心要求。rtex-ts 单独测量包含同步缓冲区处理的延迟；上游论文约 1 ms 的结果不是本包的基准。

## 复现

```sh
npm ci
npm run benchmark -- --pages 10,100,300 --samples 50 --output .ai-notes/performance/local.json
```

先安装 LuaLaTeX、fontspec 和 Latin Modern Roman。合成 article 使用显式分页，每页四段；每个样本修改第一段的一个字符。常驻引擎已预热，不计首次旧段落验证探针。计时从调用 `setDocument()` 前开始，到 `ParagraphUpdate` 事件结束，包含同步文档处理、传输、TeX 和显示列表解码；不含编辑器／渲染器 IPC、字形绘制与屏幕呈现，也不代表 TeXPro 性能。

结构修改、不支持语法、PDF 回退、启动和后台收敛有不同开销。脚本也记录启动和 Node RSS，不统计整个 TeX 进程树内存。运行时避免并行构建和其他重载程序。百分位只描述这些样本，不构成延迟保证。原始结果留在 Git／npm 归档之外。

## 0.1.2 候选版本本机测量

测量日期 2026-11-11（Asia/Shanghai），Apple M1 Pro、macOS ARM64、Node 26.5.0、LuaHBTeX 1.16.0／TeX Live 2023，每份文档测量 50 次修改：

| 页数 | 源码字节数 | 编辑 → 事件 p50 | p95 | p99 | 同步编辑 p50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 | 19,321 | 2.02 ms | 2.88 ms | 3.18 ms | 0.25 ms |
| 100 | 192,571 | 3.05 ms | 3.68 ms | 4.06 ms | 1.25 ms |
| 300 | 578,171 | 5.28 ms | 7.64 ms | 9.51 ms | 3.32 ms |

这是单台机器的合成英文段落数据，不能推广为中文、数学、自定义文档类、所有平台或宿主的同等延迟。每个会话使用全新字体缓存，首次布局约耗时 13.5／14.7／19.6 秒。冷启动与完整排版仍需优化。

优化前，同一机器、相同合成文档的 0.1.1 实现初步测量了 20 个样本，编辑到事件中位数约为 6.43／32.41／190.75 ms。样本数不同，此对比用于定位问题，不是受控统计结论。

## 局部编辑减少了什么开销

段落内部修改只重新分段该段落，再平移后续 UTF-8／行位置；结构或边界修改仍使用完整平衡扫描器。稳定分段匹配使用 Map／Set，避免重复线性搜索；位置计算单次遍历源码区间。响应通过 Node 流和 POSIX FIFO／Windows 命名管道送达，去掉响应文件轮询间隔和持续增长的响应文件。旧段落探针与过期结果检查始终保留。
