# 兼容性与验证

[English](compatibility.md)

需要 Node.js 22+、独立安装的 LuaLaTeX、2021 年或更新的 LaTeX 内核，以及文档所需宏包和字体。`doctor` 检查可执行文件和支持文件，不证明所有文档依赖均已安装。

| 平台 | 实现方式 | 首次发布前证据 |
| --- | --- | --- |
| macOS ARM64 | Node 文件和进程 API、MacTeX 默认路径、POSIX 进程组 | 本机单元测试、真实 CTeX/Fandol、行内数学、多文件、TikZ 及普通导出；TeX Live 2023 |
| Linux | PATH 或指定引擎、POSIX 进程组 | 已配置单元/安装包 CI 矩阵及独立 TeX Live 作业，结果以实际运行为准 |
| Windows | `.exe` 查找、平台路径分隔符、JSON stdin、taskkill 进程树 | 已配置单元/安装包 CI 矩阵，尚未验证真实 TeX 集成 |
| macOS Intel / 其他架构 | 没有原生 npm 依赖或内置架构特定程序 | 未在本机运行验证 |

CI 矩阵在 Linux、macOS、Windows 运行单元及压缩包安装测试。Linux 作业安装 LuaLaTeX、中文和 TikZ 宏包，执行真实 TeX 测试。存在工作流不等于已通过；发布报告应链接实际结果，并保留失败或跳过的平台边界。

MiKTeX 未验证；不支持 XeLaTeX/pdfLaTeX。路径含 TeX 特殊字符 `% # { } ~ "` 或换行时拒绝。TeX 语法、文档类和字体可能有额外路径约束，建议使用简单工程名。拒绝指向工程外的符号链接文件，不递归复制符号链接目录。可信文档中已有的绝对外部引用由作者负责。

单元测试覆盖 UTF-8、中文、emoji、CRLF、控制字符、平衡范围、未完成输入、注释和逐字内容、二进制损坏、源码身份、路径、程序缺失、进程超时与清理、上游文件完整性和 CLI 协议。安装包测试离线安装实际 npm 压缩包，检查 ESM API、CLI 和支持文件。真实 TeX 测试使用临时工程，验证实时更新、后台回退、不改写原文及导出。

当前没有公开的 rtex-ts 性能基线。上游论文和 Rust 项目的延迟数据不是本实现测量值；单次本机计时只作为功能验证证据。
